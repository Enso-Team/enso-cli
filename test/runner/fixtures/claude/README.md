# Enso-authored Claude replay transcripts

No agent-host recording covers these exchanges, so they were written by hand (the
`bridge_*` ones generated by a one-off script, then committed as written). Their frames
follow the shapes of the recorded transcripts in `../agent-host/` and the Claude Agent SDK
0.3.318 types; the values are invented, and no model produced them. Each header's
`metadata.synthetic` says so, and `metadata.covers` names the behavior under test.

| Transcript | Covers |
| --- | --- |
| `ask_user_question.ndjson` | AskUserQuestion as runner input, and the captured selection in the prompt |
| `concurrent_callbacks.ndjson` | a permission and a question arriving together |
| `withdrawn_callbacks.ndjson` | the CLI withdrawing a queued callback and a pending one |
| `late_frames.ndjson` | results for other turns, and frames, a callback and a result after this turn's result |
| `bridge_bound_read_write.ndjson` | a pinned session's bound environment, and `enso` reads and writes mid-turn that do not end the turn |
| `bridge_target_not_active.ndjson` | an `enso` read refused with `target_not_active`; the agent reports it and the turn completes |
| `bridge_write_then_disconnect.ndjson` | an `enso` write succeeds, then the stream ends without a result: interrupted |
| `bridge_token_echo.ndjson` | the agent repeating the pairing token in a tool input and its reply (redacted from runner state) |

The `bridge_*` transcripts were written for runner protocol 3 (November 2026). No Enso
app, bridge or `enso` process took part: their tool results are `enso` output as
`src/errors.ts` prints it, and their `query.open` pins the bound environment with the
pairing token as `<token>`. `bridge_token_echo` carries an invented token in
`metadata.pairingToken`; it is not a real pairing.

Before relying on one of these for a behavior change, compare it with a live recording.
